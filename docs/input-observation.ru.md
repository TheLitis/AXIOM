# Наблюдение клавиатуры и gameplay touch

[English version](input-observation.md) · [Нативный адаптер](native-adapter.ru.md) · [Исторические данные взаимодействий](native-interactions.ru.md)

**Схема 5 реализована; новая нативная проверка ещё ожидается.** Контракт расширяет наблюдение входов в gameplay и читаемую сводку инспектора. Он не устанавливает, что новый ручной тест записал все запрошенные клавиши. Результаты взаимодействий, синтетического UI и ручных действий оператора для схемы 4 сохраняют исходные записи, хеши и ограничения; отсутствующие наблюдения touch не восстанавливаются.

## Что записывается

Наблюдение ограничено `UILayer` активного записываемого `PlayLayer`. Прежние hooks `keyDown`/`keyUp` уже принимают любой сырой код клавиши, дошедший до этого слоя; схема 5 делает коды читаемыми и добавляет парные touch callbacks. События, перехваченные в другом месте, ввод меню и глобальная активность клавиатуры находятся вне этой области.

| Вход | Сохранённое наблюдение | Интерпретация |
|---|---|---|
| `UILayer::keyDown` / `keyUp` | Сырой код, timestamp, направление callback и парные снимки очереди | Запись клавиши не устанавливает игровое действие или физическое нажатие |
| `UILayer::ccTouchBegan` | Сырые аргументы touch и Boolean native return | Возврат true не аутентифицирует мышь, touchscreen или игровое действие |
| `UILayer::ccTouchEnded` | Сырые аргументы touch; native return равен null | Наблюдение окончания touch сохраняет нативное изменение очереди |
| `UILayer::ccTouchCancelled` | Сырые аргументы touch; native return равен null | Отмена записывается отдельно и не создаёт вымышленное отпускание |
| `GJBaseGameLayer::processQueuedButtons` | Прежняя парная очередь и контекст обработчика | Вход и обработку можно связать только по сохранённым данным |

Выбранный путь ввода Windows передаёт события левой кнопки в обработку touch; **вход правой и средней кнопок мыши эти UILayer hooks не покрывают**. Сам сырой callback touch не определяет устройство. Движение touch также не входит в добавленный набор callbacks. Закреплённые [маршрутизация Windows](https://github.com/geode-sdk/geode/blob/2a5fd87433da47d6bf07221774f0cbb25535ae08/loader/src/platform/windows/input.cpp#L537-L592) и [преобразование кодов мыши](https://github.com/geode-sdk/geode/blob/2a5fd87433da47d6bf07221774f0cbb25535ae08/loader/include/Geode/utils/Keyboard.hpp#L91-L122) не дают основания обозначать `KEY_None` как ЛКМ или считать каждую кнопку мыши клавишей.

Аргументы touch — точные нативные `touch_id`, `view_x`, `view_y` и `timestamp`. Все четыре равны null вместе только при null входном указателе touch; частичный null отклоняется. Координаты view не являются измеренными физическими координатами экрана, единицы timestamp не установлены. Каждая строка доставки схемы 5 требует `native_return`: Boolean только для начала touch и null для поддерживаемых void callbacks. Исходный callback вызывается ровно один раз; указатель активного UILayer проверяется до чтения gameplay полей, включая общий пустой binding отмены.

## Читаемые сырые коды и изменения очереди

Названия взяты из закреплённого [Cocos `enumKeyCodes`](https://github.com/geode-sdk/geode/blob/2a5fd87433da47d6bf07221774f0cbb25535ae08/loader/include/Geode/cocos/robtop/keyboard_dispatcher/CCKeyboardDelegate.h#L29-L77), а не из аутентифицированного потока клавиш Windows или оборудования.

| Запрошенная клавиша | Сырой код | Название SDK |
|---|---:|---|
| Space | 32 | `KEY_Space` |
| W | 87 | `KEY_W` |
| Up | 38 | `KEY_Up` |
| A | 65 | `KEY_A` |
| D | 68 | `KEY_D` |
| Left | 37 | `KEY_Left` |
| Right | 39 | `KEY_Right` |

Все остальные записанные коды сохраняются с названием SDK или `Unknown Cocos key code N`. Альтернативные коды стрелок SDK остаются разными: например, `KEY_ArrowUp` (283) не объединяется с `KEY_Up` (38). `MOUSE_4`/`MOUSE_5` — сырые названия, а не доказательство физической боковой кнопки. Попадание вошедшей клавиши в игровую команду зависит от нативного mapping и контекста; вход без добавленной команды очереди не доказывает действие.

Поле инспектора `input_entry_observations`, доступное только для схемы 5, имеет `scope: recorded_uilayer_callback_entries_and_paired_queue_snapshots` и `key_code_namespace: raw_cocos_enumKeyCodes`. Упорядоченные `keyboard_edges` и `touch_edges` сохраняют каждый callback, включая повторы, неизвестные коды и cleanup. Входы сохраняют sequence/вложенность, контекст command/update/Scheduler, фазы, wall times, native return и timestamps слоя до/после. Входы клавиатуры добавляют сырой код/название, направление callback и timestamp; входы touch — точные четыре аргумента touch. `counts` включает число входов, типы событий, down/up по каждому коду и число null touch. Счётчики описывают записанные callbacks, а не аппаратные события или успешные игровые действия.

`queue_prefix_retained` проверяет, является ли вся очередь до вызова точным префиксом очереди после. Если да, `appended_queued_commands` сохраняет точный суффикс с `queue_attribution: paired_append_snapshot_only`; пустой суффикс допустим. Иначе поле добавленных команд равно null, а attribution — `unavailable_nonprefix_queue_change`. Это наблюдение парных снимков, а не изолированная причинность или аутентифицированное происхождение очереди. Сводка сохраняет `authentication_status: not_authenticated`, `physical_device: not_identified` и `game_action_mapping: not_inferred_from_callback_entry`.

Исторические схемы 1–4 сохраняют строгие исходные readers и отсутствующие поля. Повторы схемы 5 используют прежние **18 компонентов** и `native-delivery-context-v1`: сравнение между запусками исключает сырые абсолютные timestamps слоя/клавиш/очереди и отдельно сырые touch timestamps с неустановленными единицами, сохраняя диагностику их сырого равенства/первого различия. ID touch, координаты view, native return, порядок и контекст очереди остаются точными входами сравнения. Внутри попытки timestamps остаются точными сырыми значениями. Преобразование в относительное или физическое время не вводится.

Политика ввода остаётся `process-commands-scheduled-delivery-v2`. Owned replay не изменяется; синтетический UI replay по-прежнему планирует только Space для игрока 1/кнопки 1. Новые наблюдения не добавляют инъекцию клавиатуры, генерацию ввода ОС или новый replay mapping.

## Как провести ручной тест

Из корня репозитория используйте законную локальную установку игры и закреплённую сборку:

```powershell
uv sync --locked --extra dev
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-native.ps1 -Jobs 4
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-native-manual-input.ps1 -GameDirectory 'C:\path\to\Geometry Dash' -TimeoutSeconds 300
```

Runner открывает видимый sandbox с **Start AXIOM Test**. Нажмите эту кнопку, затем отдельно нажмите и отпустите Space, W, Up, A, D, Left и Right, а также нажмите/отпустите ЛКМ внутри gameplay. Дайте плоскому fixture завершиться. Новый fixture размещает последний объект на сыром X=6000; исторический ручной fixture с X=1800 остаётся отдельным payload. Timeout включает ожидание меню; незапущенный или прерванный эксперимент сохраняет логи и не становится завершённым наблюдением.

Этот путь использует нативные часы без вмешательства, driver `none`, без исходного replay и с пустым owned plan. Input source/provenance записи остаются `unknown`. Runner требует схему 5, проверяет точный хеш уровня и копирует `input_entry_observations` в `manual-result.json`. Он не требует появления всех семи клавиш: структурно корректный результат не означает полное покрытие клавиш.

Проверьте напечатанный путь данных командой `axiom native '<evidence-directory>\capture.json' --json '<evidence-directory>\inspection.json'`. Проверьте записанные down/up для каждого кода, touch, парные изменения очереди, обработку очереди и фактические requested/player receipts. Неподдерживаемая клавиша может наблюдаться без игрового действия. Сохраняйте все дополнительные события и cleanup. Нативная [обработка потери фокуса](https://github.com/geode-sdk/geode/blob/2a5fd87433da47d6bf07221774f0cbb25535ae08/loader/src/platform/windows/input.cpp#L687-L716) может создавать key-up, поэтому направление callback само по себе не доказывает физическое отпускание.

Храните утверждение оператора отдельно от нативной телеметрии. Утверждение о нажатии этих контролов не меняет сырое provenance и не аутентифицирует путь ОС/оборудования. Локальная телеметрия остаётся в игнорируемых каталогах `reports/native`; проверьте её перед публикацией. Runner восстанавливает и проверяет исходное существование и байты четырёх файлов эксперимента. Глобальный key logger или изменение поведения физического ввода не добавляются.

## Статус данных и ограничения

Новые нативная загрузка схемы 5, покрытие ручных клавиш/touch и данные исхода **ещё ожидаются**. Исторические результаты схемы 4 находятся в [журнале взаимодействий](native-interactions.ru.md). Успешный parsing, compilation или парное добавление в очередь не устанавливают полную эквивалентность обычного ввода, полное состояние движка, завершение M1, человеческую калибровку или AR.

Закреплённые [GD 2.2081 UILayer bindings](https://github.com/geode-sdk/bindings/blob/2a8b5c489ce8b49e7061b0543aa2bc5b22570063/bindings/2.2081/GeometryDash.bro#L20171-L20185) и [API CCTouch](https://github.com/geode-sdk/geode/blob/2a5fd87433da47d6bf07221774f0cbb25535ae08/loader/include/Geode/cocos/touch_dispatcher/CCTouch.h#L51-L92) подтверждают выбранные сигнатуры и сырые поля. Эти первичные источники описывают API; они не аутентифицируют отдельную запись и не заменяют данные нативного выполнения.
