# Нативный адаптер: работа и критерии M1

[English](native-adapter.md) · [Архитектура](architecture.md) · [Телеметрия](telemetry-protocol.md) · [Требования к конечной системе](end-goal-requirements.ru.md)

Первая область интеграции — **Windows x64, Geometry Dash 2.2081, classic-уровни с обычным стартом, фиксированные моды/настройки и явная политика capture или owned-channel replay**. Целевой SDK — Geode 5.8.2. Это ограниченная область проверки; она не означает поддержку всех механик classic-уровней и всех установленных модов.

M1 должен подтвердить запись и повторяемое воспроизведение в настоящей игре. Он не устанавливает человеческую модель, не находит все допустимые маршруты и не присваивает настоящие AR. Компиляция, установка, фактическая загрузка, запись исхода и повторяемость реплея — отдельные этапы доказательства. Этот документ и собранный пакет сами по себе не подтверждают проверку во время работы игры.

## Возможности и ограничения

| Возможность | Что требуется проверить для M1 | Ограничение |
|---|---|---|
| Идентичность игры и адаптера | Хеш бинарника игры; версии runtime Geode, SDK, bindings и адаптера | Одной строки версии недостаточно |
| Classic, обычный полный старт | Короткий воспроизводимый тест; затем матрица проверенных механик | Произвольный classic-уровень автоматически не становится поддержанным |
| Запись ввода | Порядок игровых нажатий/отпусканий, игрок, кнопка, стадия hook и часы | Не измеряет аппаратное поступление, задержку или человеческое происхождение события |
| Воспроизведение | Явно подготовленное расписание до обработки команд, настоящее начало | Перевод наблюдаемого ввода и внешних форматов реплея ещё не проверен |
| Управление каналом реплея | Блокировать и записывать все неинжекторные `handleButton` requests во время реплея | Происхождение engine/human неизвестно; прямой вызов метода игрока обходит эту границу |
| Исходы | Смерть и настоящее финальное завершение движка в том же запуске | Выживание на участке или процент прогресса недостаточны |
| Состояния игрока | Явный состав полей и стадия их считывания | Координаты не являются полным состоянием движка |
| Пауза, сброс, выход | Прерывание на наблюдаемых native callbacks | Потеря фокуса покрыта только при вызове наблюдаемого pause callback; остальные пути требуют теста |
| Snapshot/restore | Отдельная будущая проверка | Не заменяет первый полный реплей из начала |
| Измерение окон | После подтверждения повторяемости | Успешные точки конечной сетки не доказывают непрерывное допустимое окно |
| CBF и другие моды ввода/физики | Отдельные будущие конфигурации | Их данные нельзя смешивать с vanilla |
| Platformer, другие версии игры и ОС | Отдельные области поддержки | Наличие bindings не является подтверждением совместимости |
| Человеческая калибровка и AR | Следующие научные этапы | Успешный макрос не устанавливает человеческую сложность |

Сохраняй состав установленных и загруженных модов и настройки, способные влиять на ввод, расписание, физику и игру. Первые тесты выполняются в контролируемой конфигурации. Неожиданный мод или настройка остаётся в manifest и означает непроверенную конфигурацию, а не исчезает из записи ради совместимости.

[Фиксированная официальная конфигурация SDK](https://github.com/geode-sdk/geode/blob/2a5fd87433da47d6bf07221774f0cbb25535ae08/CMakeLists.txt) рассчитана на GD 2.2081 и требует актуальный компилятор: Clang 19+ либо MSVC 19.44+. По умолчанию bindings берутся из изменяемой ветки; build-скрипт AXIOM использует фиксированный checkout. Совместимость во время работы подтверждается следующими проверками.

| Зависимость сборки | Фиксированная версия |
|---|---|
| Geode SDK 5.8.2 | `2a5fd87433da47d6bf07221774f0cbb25535ae08` |
| Geode bindings | `2a8b5c489ce8b49e7061b0543aa2bc5b22570063` |
| Geode CLI | 3.9.0; SHA-256 скачанного архива проверяется скриптом |

В MSVC-сборке также используется один ограниченный link alias для `CCFileUtilsWin32::getPathForFilename`: фиксированный SDK объявляет метод public, а его Windows x64 cocos import symbol имеет protected access decoration. Остальная сигнатура совпадает. Alias обеспечивает ссылку vtable тестового subclass без изменения SDK; это не общее исправление для другой ABI, платформы или версии SDK. Сохраняй диагностику линковки и всё равно выполняй runtime-проверку writable path. [Фиксированное объявление](https://github.com/geode-sdk/geode/blob/2a5fd87433da47d6bf07221774f0cbb25535ae08/loader/include/Geode/cocos/platform/win32/CCFileUtilsWin32.h)

Из PowerShell в корне репозитория:

```powershell
powershell -File .\scripts\build-native.ps1 -Jobs 4
$nativePackage = Join-Path (Get-Location).Path (Get-Content -LiteralPath .\.tools\native-package-path.txt -Raw)
Get-FileHash -LiteralPath $nativePackage -Algorithm SHA256
```

Скрипт размещает зависимости в игнорируемом `.tools`, использует установленные Visual Studio x64 C++ tools и CMake и обычно собирает пакет в `native/build`. Если кэш относится к прежнему расположению проекта, скрипт сохраняет его и пакет, выбирая отдельный `.tools/native-build-<hash>`. Конфликтующий выбранный кэш отклоняется. Только успешная сборка с непустым пакетом записывает `.tools/native-package-path.txt`; подготовка sandbox разрешает указанный относительный путь внутри проекта. Явный `-NativePackage` имеет приоритет, а без маркера используется прежний пакет `native/build`. Существующие checkout с другим commit или изменениями сохраняются, а сборка останавливается. Сборка, установка и запуск игры — отдельные действия. Для первой проверки нужна изолированная среда игры и сохранений; личные сохранения не используются для испытания пакета.

## Управление, тестовая копия и локальные файлы

ID мода — `axiom.native-capture`. **Enable local capture** (`capture-enabled`) и **Enable AXIOM command replay** (`replay-enabled`) по умолчанию выключены. Включение начинает запись при следующей успешной `PlayLayer::init` или reset. Выключение действующей опции прерывает попытку при следующем вызове обработки команд; истинный launch flag оставляет опцию включённой даже при выключенной настройке. Эквивалентные явные аргументы запуска: `--geode:axiom.native-capture.capture=true` и `--geode:axiom.native-capture.replay=true`. Надпись `AXIOM CAPTURE`/`AXIOM REPLAY` и журнал loader сообщают об активной записи. Реплей читает фиксированный локальный файл `replay.json` из каталога сохранений мода; экспорт идёт в его подкаталог `captures/`. Отправки по сети нет.

Текущая input policy — `process-commands-pre-hook-owned-input-v1`. Обычный capture наблюдает и передаёт ввод. При активном контролируемом реплее оригинальный `handleButton` получает только запрос с одноразовым разрешением инжектора; остальные запросы сохраняются как blocked diagnostics и не передаются, включая native cleanup requests. Происхождение заблокированного запроса неизвестно: это может быть движок или живой ввод. Прямой вызов player push/release обходит границу handler и остаётся неподдержанным путём вмешательства. Это явная экспериментальная политика; её эквивалентность обычной немодифицированной доставке ввода не установлена.

Для фиксированного бинарника игры подготовь игнорируемую тестовую копию, указав настоящий каталог локальной установки:

```powershell
powershell -File .\scripts\prepare-native-sandbox.ps1 -GameDirectory 'C:\path\to\Geometry Dash'
```

Подготовка копирует локальные бинарники, устанавливает пакет только в `.tools/runtime/geode/mods`, связывает `Resources` с установленными ресурсами и создаёт тестовый payload. Игра не запускается, личные сохранения не копируются. Неожиданный хеш игры, другая junction ресурсов или посторонние моды приводят к отказу. Тестовую копию и игровые ресурсы нельзя публиковать вместе с проектом.

В изолированном loader profile `AXIOMSandbox` задано `auto-check-updates: false`; подготовка отклоняет pending `.tools/runtime/geode/update`, способный заменить фиксированный loader при следующем запуске. Отключение проверки обновлений не отменяет уже подготовленное обновление. Проверяй runtime-версию loader и хеши бинарников на каждом повторе, включая перезапуски; строка версии SDK не восстанавливает изменившийся runtime.

До запуска подтверди изоляцию личных путей сохранения и сохрани журнал файлов до/после теста. Тестовые runtime/save roots должны быть новыми обычными каталогами, а не symlink/junction в личные данные: равенство canonical paths само по себе не обнаружит перенаправленный тестовый save directory. Явная junction `Resources` относится к установленным ресурсам и не используется для сохранений. Затем из корня репозитория:

```powershell
$sandboxExe = Join-Path (Get-Location).Path '.tools\runtime\AXIOMSandbox.exe'
Start-Process -FilePath $sandboxExe -WorkingDirectory (Split-Path -Parent $sandboxExe) -ArgumentList '--geode:axiom-sandbox=true' -WindowStyle Hidden
```

Помощник работает только при имени executable `AXIOMSandbox.exe` и явном sandbox-аргументе. Перед созданием несохранённого тестового уровня он проверяет writable path движка, затем включает запись. Этот smoke test проверяет загрузку/oracle; он не подтверждает содержательное воспроизведение кнопок, все пути сохранения и все механики.

Автоматические эксперименты подготавливают тестовую копию и завершают только запущенные ими процессы:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-native-clock-study.ps1 -GameDirectory 'C:\path\to\Geometry Dash' -Repetitions 3
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-native-smoke.ps1 -GameDirectory 'C:\path\to\Geometry Dash' -Fixture spike -ClockPolicy fixed-scheduler-240 -Repetitions 3
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-native-controls.ps1 -GameDirectory 'C:\path\to\Geometry Dash' -ClockPolicy fixed-scheduler-240
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-native-matrix.ps1 -GameDirectory 'C:\path\to\Geometry Dash' -Repetitions 3
```

Smoke-скрипт требует исполнения всего расписания press/release и нативных callbacks игрока, затем завершается ошибкой при расхождении точного сравнения. Контрольный скрипт требует нативной смерти на созданном препятствии и отказа от replay с неверным уровнем. Исследование часов сохраняет шесть комбинаций, включая расхождения, и требует успешного сравнения обоих случаев с фиксированным Scheduler. Каждый скрипт сохраняет локальные доказательства и восстанавливает прежние fixture, replay и настройки sandbox-мода/loader — точные байты и факт существования, включая ошибку эксперимента. Указанный каталог результатов smoke не должен существовать заранее. `-ExecutionPolicy Bypass` действует только для запускаемого процесса PowerShell. Фактические результаты и открытые критерии находятся в [первом журнале](native-validation.ru.md) и [исследовании часов](clock-investigation.ru.md).

[Матрица тестовых сценариев](native-fixture-matrix.ru.md) задаёт созданные уровни, точные планы ввода, последовательности режимов до анимации финиша и ожидаемые исходы отдельно от записанного доказательства. Скрипт сравнивает весь записанный replay до terminal между повторами и проверяет выбранный отклик на ввод относительно пустого owned-input плана. Команды `fixtures`, `fixture-check` и `fixture-response` проверяют присланные файлы без запуска или аутентификации движка. Корректный JSON с расхождением может иметь CLI exit 0; скрипт читает итоговый статус перед признанием сценария успешным.

Нужно различать два каталога сохранений. Помощник направляет writable paths движка `CCFileUtils` в `.tools/runtime/sandbox-saves`. Geode независимо получает save root из имени executable: обычно `%LOCALAPPDATA%\AXIOMSandbox`. Поэтому записи мода обычно находятся в `%LOCALAPPDATA%\AXIOMSandbox\geode\mods\axiom.native-capture\captures`, а исходный реплей — в соседнем `replay.json`. Если создать AppData-каталог не удалось, Geode использует каталог executable; фактический путь нужно проверить в runtime, а не предполагать. [Фиксированная реализация Windows save root](https://github.com/geode-sdk/geode/blob/2a5fd87433da47d6bf07221774f0cbb25535ae08/loader/src/platform/windows/util.cpp), [путь сохранений мода](https://github.com/geode-sdk/geode/blob/2a5fd87433da47d6bf07221774f0cbb25535ae08/loader/src/loader/ModImpl.cpp)

## Часы и порядок hooks

| Наблюдение | Что оно означает |
|---|---|
| Время input hook | Когда адаптер наблюдает доставку запроса в определённую функцию игры |
| Индекс обработки команд | Порядковый номер вызова с сохранёнными `dt` и half/last-флагами |
| Обновления игры и Scheduler | Парные вход/выход, вложенность, исходный и переданный `dt`, границы команд и флаги нативной фазы |
| Сумма исходных callback `dt` | Сумма переданных аргументов; её смысл как simulation time независимо не установлен |
| Монотонное время компьютера | Продолжительность записи и затраты на сбор данных |
| Время отображения кадра | Неизвестно без отдельного наблюдения |
| Аппаратное поступление и device-to-photon latency | Неизвестны без отдельного измерительного метода |

В [фиксированных bindings 2.2081](https://github.com/geode-sdk/bindings/blob/2a8b5c489ce8b49e7061b0543aa2bc5b22570063/bindings/2.2081/GeometryDash.bro) есть `handleButton(bool down, int button, bool isPlayer1)` и `processCommands(float dt, bool isHalfTick, bool isLastTick)`. Вызов обработки команд не равен автоматически визуальному кадру или физическому тику частоты 240 Гц. Значение `true` у `isPlayer1` обозначает первого игрока. Порядок событий, флаги и стадия наблюдения/ввода должны сохраняться.

Аргумент запуска `--geode:axiom.native-capture.clock-policy=<policy>` выбирает явный режим часов:

| Режим | Аргумент оригинального обновления |
|---|---|
| `native` (по умолчанию) | Исходное значение без изменения |
| `fixed-base-60` | Float32 `1/60` один раз на исходный вызов `GJBaseGameLayer::update` у инициализируемого/текущего PlayLayer |
| `fixed-scheduler-240` | Float32 `1/240` один раз на исходный вызов `CCScheduler::update` во всём защищённом sandbox-процессе, включая время до начала записи |

Режимы с фиксацией требуют `AXIOMSandbox.exe` и явного sandbox-аргумента. Они меняют условия эксперимента и не устанавливают измеренную частоту реального времени или соответствие обычной игре. Нет аккумулятора, дополнительных update-вызовов, ручного обновления ActionManager, коррекции позиции/вращения или восстановления checkpoint. Manifest сохраняет режим, hook, рациональный шаг и область действия; исходные аргументы и wall cadence остаются наблюдаемыми. Поддержанная тестами область указана в [исследовании часов](clock-investigation.ru.md).

Вызов оригинального input handler не доказывает время аппаратного события и принятие запроса последующими стадиями игры. Если принятие, отклонение и буферизация отдельно не наблюдаются, запись обозначается как доставленный в hook ввод. События реплея не являются человеческими наблюдениями.

[Приоритеты Geode hooks](https://github.com/geode-sdk/docs/blob/main/tutorials/hookpriority.md) различают код до и после оригинального вызова. Фактическая стадия адаптера должна быть описана. Отложенный вызов может заново войти в hook; нужны явная защита реплея и синхронный порядок. Изменение приоритетов или другой input-мод означает новую проверяемую конфигурацию.

## Порядок работы

1. Сохрани точный короткий уровень и manifest среды. Используй законно установленную игру и локальный каталог результатов. Бинарники игры, сохранения и личные записи не добавляются в Git.
2. Собери пакет через `scripts/build-native.ps1` и сохрани его хеш. Общие команды Geode могут устанавливать пакет через CLI profile; упаковка AXIOM должна отключать это поведение, чтобы установка оставалась отдельным явным действием. [Официальная реализация упаковки](https://github.com/geode-sdk/geode/blob/2a5fd87433da47d6bf07221774f0cbb25535ae08/cmake/GeodeFile.cmake)
3. Перезапусти игру после установки. Подтверди фактическую загрузку по журналу loader и статусу адаптера. Скопированный файл или включённая галочка этого не заменяют. Проверь manifest текущей игры и загруженных модов.
4. Явно включи запись. Начни обычную classic-попытку из настоящего начала с отпущенными кнопками. Сохрани завершение, смерть либо явно обозначенное прерывание. Повтори после чистого полного сброса.
5. До публикации проверь запись локально: payload, часы, начальное состояние, порядок нажатий/отпусканий, sampled states и финальный исход. Неизвестные поля не заменяются номинальным FPS или выдуманным временем принятия ввода.
6. Подготовь native-расписание AXIOM для того же настоящего начала с точными level/environment hashes и явными pre-hook indices. Запиши его минимум дважды при включённом реплее; несовпадение уровня или среды должно отклоняться. Сохрани blocked-request diagnostics и проверь отсутствие неподдержанных прямых вызовов методов игрока. Пауза, потеря фокуса, выход, неожиданный сброс или изменение среды прерывают либо аннулируют сравнение; отдельно проверь, какие пути потери фокуса вызывают pause hook.
7. Выполни повторы с заранее заданными правилами сравнения. Сохрани все попытки, ошибки и расхождения. Завершение подтверждает физический witness только для запуска и конфигурации из его пакета доказательств.
8. После проверки повторяемости измеряй разрешение расписания и perturbations, продолжая каждый запуск до финального oracle. Сбор человеческих данных и AR относятся к следующим этапам.

Наблюдаемую запись сейчас нельзя автоматически превратить в точное воспроизведение. Запрос между вызовами получает индекс последнего начатого вызова, а replay index `n` вводит событие перед вызовом `n`. Прямое копирование сдвигает фазу. M1 принимает только специально подготовленные native-расписания; импорт GDR и преобразование наблюдаемых событий ещё не устанавливают соответствие этим часам.

Формат локального `replay.json`:

```json
{
  "schema_version": 1,
  "kind": "native_replay",
  "clock": "processCommands_call_index",
  "level_sha256": "<64 lowercase hex characters>",
  "environment_sha256": "<64 lowercase hex characters>",
  "inputs": [
    {"command_index": 20, "player": 1, "button": 1, "pressed": true},
    {"command_index": 30, "player": 1, "button": 1, "pressed": false}
  ]
}
```

Эти индексы показывают формат, а не проверенный маршрут. События используют целые индексы 1–20 000, player 1–2, button 1–3, Boolean `pressed` и порядок массива при одинаковых индексах. Поддерживается до 4 000 запланированных событий; пустое расписание допустимо для автоматического теста. Разрешены только описанные поля; дубли ключей, вложенность выше 64 и исходные файлы больше 16 MiB отклоняются. Смерть/завершение может возникнуть раньше будущих событий расписания: validator сообщает о неисполненном хвосте и оценивает только выполненный префикс до terminal.

## Формат записи и сравнение

Текущая нативная запись имеет schema 2, `kind: native_capture`; один файл содержит одну `attempt`. Inspector также принимает schema 1, сохраняя отсутствие новых update/phase-наблюдений; у старых input policy отсутствующий поток blocked requests явно отмечается как незаписанный. Происхождение объявляется как `native-engine-capture` с `independently_verified: false`: JSON parser не удостоверяет происхождение записи. Level hash обозначает точные байты `GJGameLevel::m_levelString`, а не восстановленную геометрию столкновений. Source-tree digest коллектора обозначает скомпилированные native sources, CMake и manifest мода, даже если commit старше локальных изменений. Среда имеет хеш компактного UTF-8 JSON с рекурсивно отсортированными ключами и `configuration_complete: false`. Поля игрока отмечены `state_completeness: selected_fields_only`; это не восстанавливаемый snapshot.

Trace начинается с command index 0 после инициализации/сброса, затем сохраняет непрерывные вызовы обработки команд с `dt_seconds`, `is_half_tick` и `is_last_tick`. Начальный timing равен нулю. Индекс увеличивается до оригинального callback, обычные sampled states записываются после него. Terminal snapshot из `levelComplete`/`destroyPlayer` сохраняется отдельно: он может отличаться от последнего post-processing sample и сравнивается отдельно. Экспорт ждёт возврата из охватывающих command/update/Scheduler/ending-phase hooks.

Schema 2 добавляет `attempt.updates`, `attempt.scheduler_updates` и `attempt.phase_events`. Парные update-записи сохраняют границы команд, вложенность, исходный/переданный `dt`, исходные флаги ending/completion и wall timestamps. Trace и terminal сохраняют sequence охватывающих update/Scheduler; для вызова, уже начатого к моменту записи, принадлежность неизвестна. Парные наблюдения `PlayLayer::playEndAnimationToPos` задают нативный переход к завершающей анимации без предположений по проценту или координате. Лимиты: 20 000 команд, 20 000 записей на каждый update-поток, 256 phase events и 16 MiB на исходный файл. Отсутствующие/усечённые записи аннулируют доказательство terminal.

Доставленные `inputs` сохраняют запрос в `handleButton` и наблюдаемые callback-фазы push/release игрока, включая native return value, когда он доступен. Sources различают observed/replay; происхождение attempt — unknown/replay. Наблюдаемая доставка не доказывает человеческое авторство. Отдельный `attempt.blocked_inputs` присутствует всегда и пуст для observation capture. Каждый blocked diagnostic имеет собственную непрерывную sequence, command index, player, исходный signed-int32 button, pressed state, `source: unknown` и монотонный wall timestamp. Delivered phase и native return отсутствуют: оригинальный handler не вызывается. Доставленные и заблокированные записи делят лимит 12 000 records. Начало различает `level_start`, `practice`, `start_position` и `unknown`. Указатель второго игрока может существовать при его неактивности; активность не записывается, поэтому одни эти поля не переопределяют native terminal callback.

В `axiom.native` доступны Python API `inspect_native_capture(path)` и `compare_native_captures([path_a, path_b, ...])`. Inspector проверяет структуру присланных данных. Сравнение полного старта требует совпадения challenge/environment/collector, точного хеша исходного реплея и сохранённого расписания, разных attempt IDs, непрерывного trace до terminal и полной integrity без пропущенных записей и ошибок. Practice/start-position записи не удовлетворяют этому сравнению. Успешный статус — **`recorded_subset_consistent`**, а не полная детерминированность и не сертификация M1. Сравнивается только записанный набор x/y, y velocity, rotation, mode и death; незаписанные world/trigger states не проверены.

После установки Python-пакета можно проверить локальную запись и сравнить от двух до шестнадцати контролируемых повторов:

```powershell
axiom native 'C:\local-evidence\capture-a.json' --json .\reports\native\inspection.json
axiom native-compare 'C:\local-evidence\replay-a.json' 'C:\local-evidence\replay-b.json' --json .\reports\native\comparison.json
```

Сравнение требует точного равенства исходных аргументов command callbacks, выбранных состояний с вращением, доставленных input phases/order/native return values, расписания, положения/состояния terminal, нативных фаз, update contexts, переданных update/Scheduler records и phase events. Исходные входящие update-аргументы и wall timestamps сохраняются отдельной диагностикой; переданные значения участвуют в проверке равенства. В режиме `native` переданное равно исходному, поэтому его переменные аргументы тоже сравниваются. Различия blocked requests сообщаются отдельно. Равенство набора не устанавливает побайтовое равенство файлов или всего потока запросов. `pre_end_animation_diagnostics` использует настоящую записанную границу native callback; совпадение префикса не отменяет расхождение полного запуска. Сумму callback `dt` нельзя назвать проверенным simulation time. Aborted/error и неполные записи отклоняются как доказательство terminal; их файлы и журналы нужно сохранять как неудачные попытки.

## Проверяемый первый checkpoint

Этот список служит журналом релиза и доказательств. Невыполненный пункт остаётся непроверенным; сборка не закрывает пункты работы в игре.

- [ ] Сохранены хеши игры, loader, SDK, bindings, адаптера и конфигурации.
- [ ] Пакет собран; сохранены compiler/configuration/log, commit и SHA-256 пакета.
- [ ] Адаптер действительно загружен в точной версии игры; сохранён runtime handshake/log.
- [ ] Экспортирован настоящий полный запуск от обычного начала до финального события завершения движка.
- [ ] Сохранены контрольная смерть и прерывание; они не обозначены как завершение.
- [ ] Есть содержательный тест с нажатием и отпусканием. Автоматический уровень без ввода проверяет загрузку/oracle, но не input playback.
- [ ] Проверены player/button/order, часы и стадия hook, исходные callback timings, начальные удержания и принадлежность финального события запуску.
- [ ] Подготовленное расписание выполнено из настоящего начала; требуется точное равенство объявленных состояний, callback arguments, input phases/order и terminal. Wall duration сохраняется как диагностика; неисполненный хвост расписания явно указан.
- [ ] Выполнено и опубликовано заданное количество повторов на явной матрице тестов и конфигураций, включая ошибки и расхождения.
- [ ] Проверены отклонение другого уровня/build/input policy, блокировка/диагностика неинжекторных запросов и неподдержанные пути прямого вызова методов игрока.
- [ ] Проверены пауза, потеря фокуса, сброс, выход и изменения настроек; старая запись не выдаётся за новый полный запуск. Указаны пути, не наблюдаемые текущими callbacks.
- [ ] Измерены затраты записи и native replay throughput относительно описанного контроля.
- [ ] Опубликованы матрица проверенных возможностей, непроверенные механики и неподдержанные модификации.
- [ ] Сохранён воспроизводимый локальный отчёт; для публикации отобраны разрешённые и проверенные данные.

Восстановление checkpoint — отдельный этап: достижимая граница берётся из настоящего префикса, восстанавливается и сравнивается с непрерывным продолжением. Нужно переносить world/trigger/clocks/held inputs и остальные состояния, влияющие на будущее. Неполный snapshot не позволяет искусственно собрать доказательство полного прохождения.

## Приватность и смысл результата

Запись локальная, добровольная и ограничена игрой. Перехват игровых кнопок не является системным клавиатурным журналом. Пароли, приватный чат, clipboard и другие приложения не собираются. Для проверки не требуется upload. Перед публикацией проверь payload, названия, моды и traces: они могут содержать частную или идентифицирующую информацию. Требования согласия и хранения описаны в [протоколе телеметрии](telemetry-protocol.md).

Native-инструментирование может производить данные настоящего движка, но присланный файл автоматически не удостоверяет своё происхождение. Проверка структуры файла, завершение в одном запуске, наблюдаемая повторяемость и независимое воспроизведение — разные доказательства. Завершение контролируемого реплея относится к его owned-channel policy и не устанавливает эквивалентное обычное человеческое/vanilla-исполнение. Конечное число успешных тестов не доказывает универсальную детерминированность; неудачный поиск не доказывает невозможность; результат M1 не измеряет человеческий предел и откалиброванный AR.
