# Ограниченная диагностика нативного старта

[English version](native-startup.md) · [Ввод Windows](windows-input.ru.md) · [Нативный адаптер](native-adapter.ru.md) · [Roadmap](roadmap.md)

**14 октября 2026: диагностика старта и проверки отказов наблюдателя готовы; живая проверка ввода Windows остаётся открытой.** На этом этапе адаптер собран, а сохранённые файлы изучены без запуска Geometry Dash. Причина трёх прежних неудачных стартов, завершённая запись схемы 7 и полный критерий M1 пока не установлены.

## Что сохраняется

Runner ввода Windows снимает ограниченную опись файлов до запуска принадлежащего ему игрового процесса. После выхода или завершения процесса runner сохраняет отдельный снимок manifest, копирует выбранные стартовые файлы и записывает метаданные сбора в `startup_diagnostics`. Основная ошибка наблюдения, ошибки диагностики и `cleanup_errors` остаются отдельными. `process_cleanup` указывает, был ли выход замечен до очистки, запрашивалось ли завершение процесса и какой естественный exit code доступен. Истечение срока явно обозначается как timeout; выход после команды завершения от runner не превращается в естественный выход.

Диагностический архив имеет отдельную схему 1 и не является игровой записью. Он включает исходные байты, размеры, SHA-256 и состояния чтения для непосредственных `geode/logs/*.log`, выбранных текстовых/log файлов в `geode/crashlogs`, `_geode_early_error.txt` и заявленных stdout/stderr runner рядом с переданным manifest. Профили игры и произвольные деревья файлов не сканируются. Symlink/reparse paths, нестабильное чтение и перенаправленные предки отклоняются; отсутствие, пустота, удаление, невозможность чтения и превышение ограничений остаются явными.

Ограничения сбора: 64 выбранных файла логов, 256 элементов каталога на группу, 4 MiB на файл, 16 MiB суммарных байтов логов и 2 MiB на входной JSON. Инспектор сохраняет до 2048 наблюдений маркеров. Неполнота или неподдерживаемая кодировка отражаются в результате. Нормализация ANSI/CRLF и BOM UTF-16 используется только для поиска маркеров; исходные байты не меняются.

## Как читать отчёт о старте

Инспектор распознаёт ограниченный набор сообщений Geode/AXIOM: завершение загрузчика, загрузку/отказ адаптера, вход и возврат инициализации приложения/меню, изоляцию сохранений, готовность ручного теста, запрос запуска fixture и начало/export записи. Возврат инициализации сохраняет bool; запрос сцены или строка export не доказывают завершение прогона. Отсутствие маркера означает, что он не обнаружен в сохранённом тексте.

| Связь источника | Что позволяет отчёт |
|---|---|
| Нет описи перед запуском | `retrospective_runtime_unbound`; маркеры сохраняются без установления готовности текущей попытки |
| Прежний файл runtime не изменён | Только исторические наблюдения маркеров |
| Прежний файл runtime с тем же именем изменён | Новые байты сохраняются, но строки не привязаны к попытке |
| Новый файл runtime после полной описи, снятой до старта процесса | Может установить готовность ручного теста на уровне лога при наличии точного маркера |
| Stdout/stderr runner | Диагностические наблюдения; готовность текущей попытки не устанавливают |

Даже опись перед запуском не аутентифицирует принадлежность файла процессу: `authenticated_process_membership` остаётся false. Готовность — условие на уровне лога, а не доказательство gameplay, физического ввода, полного состояния движка или эквивалентности обычному вводу. Знаковые exit codes Windows сохраняют исходное значение и беззнаковое 32-битное представление; ни одно не устанавливает причину сбоя. `cause` остаётся `unknown`, `m1_gate` — `not_established`.

## Команды без запуска игры

Эти команды читают и сохраняют диагностические файлы; игру и ввод не запускают. Пути должны быть обычными, выходные данные — новыми, а файл результата инспекции — вне каталога архива.

```powershell
uv sync --locked --extra dev
uv run --locked axiom native-startup-baseline '.tools\runtime-new' --output 'reports\before-start-new.json'
uv run --locked axiom native-startup-collect '.tools\runtime-new' --attempt-manifest 'reports\attempt-new\startup-manifest-snapshot.json' --baseline 'reports\before-start-new.json' --output 'reports\startup-review-new'
uv run --locked axiom native-startup 'reports\startup-review-new\bundle.json' --json 'reports\startup-review-new.inspection.json'
```

Опись снимается до заявленного старта процесса; runner делает это сам для будущих попыток ввода Windows. Для старого runtime без такой описи убери `--baseline` и сохрани ретроспективную атрибуцию. Команды описи и сбора выводят метаданные в stdout; `--json` относится к инспекции. Python-интерфейсы: `snapshot_startup_logs`, `collect_startup_evidence` и `inspect_startup_evidence` в `axiom.startup`.

## Сохранённые неудачные старты

Отдельное ретроспективное исследование сохраняет три исходных manifest и выводы runner неизменными. Старые manifest не связывали runtime-логи с процессами, поэтому вновь сохранённые логи не получают аутентифицированную принадлежность задним числом. Все три диагностические инспекции полны в своей заявленной области; готовность текущей попытки не установлена, причина неизвестна.

| Старая попытка | Сохранённые наблюдения маркеров | SHA-256 лога загрузчика |
|---|---|---|
| Первый новый пакет | Завершение загрузчика, загрузка адаптера, явный отказ guard | `c1aa47e34995ba6a80f8493661b3eae1c17f4bc5d6f4ebac68e1e6583e5223bc` |
| Второй новый пакет | Завершение загрузчика и загрузка адаптера | `e2e6b3b99a20807461b372eff6c925ac61d4d6edf7901ce0881f67038ad9d91d` |
| Контроль со старым пакетом | Сохранённых стартовых маркеров нет | Лог загрузчика не сохранён |

Два первых лога имеют соответственно 11 566 и 11 480 байтов. Ни один не сохраняет маркеры изоляции сохранений, готовности ручного теста, запуска fixture или записи. SHA-256 индекса исследования: `6969cf27d14de751193f4858999a6370367b2b1c3dd87ef0000335ddb7dc202e`. Отдельный аудит на той же машине, только со стандартной библиотекой, прошёл **79 проверок байтов, идентичности и маркеров без расхождений**, без импорта AXIOM и запуска игры. SHA-256 его отчёта: `d791ab72bb88af132cf08cc9b1d4b5df334adead09f1e55316712e974a6e5eda`. Это проверки архивных файлов, а не независимое выполнение движка.

Заголовок «Attention» не определяет причину старта. Закреплённые исходники Geode содержат два разных диалога: [чистый режим по Alt+Shift](https://github.com/geode-sdk/geode/blob/2a5fd87433da47d6bf07221774f0cbb25535ae08/loader/src/platform/windows/main.cpp#L154-L168) до `geodeEntry` и [безопасный режим по Shift](https://github.com/geode-sdk/geode/blob/2a5fd87433da47d6bf07221774f0cbb25535ae08/loader/src/load.cpp#L85-L100) до настройки logger. Текст диалога и состояние нужных клавиш старого контроля не сохранены. Два новых лога достигают завершения загрузчика; их выход не объясняется ожиданием этих более ранних диалогов. Обход guard и вмешательство в модификаторы/ввод в этот этап не входят.

## Программные проверки и идентичность сборки

Нативный наблюдатель теперь фиксирует потерю покрытия при уничтожении сохранённого основного/raw окна или утрате установленного hook и проверяет принадлежность перед повторным использованием hook. Историческое успешное подключение отделено от живого покрытия; обычное отключение не искажает его. [Протокол кандидатов v2](windows-input.ru.md) учитывает закреплённое преобразование стороны Control/Alt, оставляя неизвестное преобразование раскладки неразрешённым.

Нативный стенд компилирует production observer с настоящим matjson и подставными интерфейсами Windows/Geode. Исправленный контроль до фикса обнаружил **5 ошибок в 20 сценариях / 81 проверке**; итоговый стенд прошёл **23 сценария / 112 проверок**. Проверяются передача сообщения, return/last-error, подключение и rollback, вложенность, ошибки чтения raw, ограничения, исключения, замена цепочки, завершение callbacks и отклонение утраты окна. Настоящий цикл сообщений Windows и игра не запускаются.

Тесты диагностики старта прошли **50 тестов, 2 symlink-теста пропущены** из-за отсутствующих прав на создание. Проверка отклонения настоящего Windows junction прошла. Четыре отдельные проверки консольных процессов прошли для быстрого exit 0, exit 2 со stderr, сохранения существующих выходных файлов и отклонения пути вне workspace. Полный набор прошёл **880 тестов и 83 subtests, с теми же 2 пропусками**; Ruff прошёл на 70 Python-файлах. Windows CI выполняет консольные проверки, нативный CI собирает адаптер и запускает стенд отказов без игры.

Идентичность дерева использует рекурсивные относительные пути `native/src/*.cpp`/`*.hpp` в ordinal-порядке, затем `CMakeLists.txt` и `mod.json`, с хешированием записей `path:SHA-256\n`. Идентичность сборки не включает позднейший коммит документации. Нативные пакеты, логи, записи и отчёты аудита остаются локальными игнорируемыми файлами.

На этом этапе нового нативного выполнения нет; временные окна, прогнозы для людей и AR не установлены.
