# Диагностика частоты нативных вызовов

[English version](native-cadence.md) · [Записанный replay](recorded-replay.ru.md) · [Ввод Windows](windows-input.ru.md) · [План](roadmap.md)

`axiom native-cadence` описывает записанные потоки команд, игрового update и Scheduler в одном файле. Он рассчитывает количества, аргументы вызовов, интервалы между входами, парные интервалы настенных часов, принадлежность команд и группы фаз. Geometry Dash для этого не запускается.

```sh
axiom native-cadence examples/native/synthetic-clock-a.json --json reports/synthetic-cadence.json
axiom native-cadence path/to/your/capture.json --json reports/cadence.json
```

Первый пример синтетический. Во второй команде укажи свою сохранённую запись. Python API: `axiom.cadence.inspect_native_cadence(path)`. Схемы capture 1–7 проверяет существующий строгий reader; для схемы 1 отсутствующие потоки отмечаются как незаписанные. Результат — отдельный отчёт `native_cadence_diagnostics` схемы 1; формат вывода `axiom native` не меняется.

## Правила измерения

| Величина | Расчёт и смысл |
|---|---|
| Число команд | Строки trace после начального состояния; строка ноль не является командой |
| Количество на секунду заявленного времени | Число команд или строк потока, делённое на заявленное время до terminal |
| Частота интервалов между входами | `(число входов − 1) / (последний вход − первый вход)` отдельно в каждом потоке; недостаточная или нулевая длительность даёт явный статус недоступности |
| Интервалы между входами и парные длительности | Эмпирические p50/p95/p99 методом ближайшего ранга, минимум, максимум, среднее и сумма; доверительный интервал не оценивается |
| Исходный и переданный `dt` | Раздельные распределения аргументов, число нулей и точных неравенств; сумма аргументов не является откалиброванным временем симуляции |
| Сумма и объединение интервалов | Отдельно в каждом потоке, включая сводку корневых вызовов; вложенные интервалы нельзя считать непересекающейся работой |
| Граница terminal | Сохраняются полные охватывающие callbacks, объединение интервалов до terminal и поздние выходы/хвосты |
| Принадлежность команд | Сохраняются прямые контексты trace, неизвестные контексты, вложенность, изменения счётчика в корневых вызовах и канонический хеш группировки |
| Группы фаз | Целые строки относятся к `start_warmup`, `normal_pre_end`, `ending`, `crosses_phase_boundary` или `unknown` по записанным счётчикам и флагам |

Строки, пересекающие смену фазы, не делятся: точное настенное время входа каждой команды не записано. Корневые интервалы команд включают вложенные, поэтому их изменения не складываются. Интервалы игрового update и Scheduler пересекаются и никогда не складываются между собой. Пустые выборки имеют null для квантилей/среднего и нулевую сумму. Неконечные результаты и изменение исходных байтов отклоняются.

Отчёт сохраняет SHA-256 исходника, схему capture, collector, точное окружение и его хеш, политику часов, испытание, маршрут ввода, terminal и заявленное происхождение. Каждая запись анализируется отдельно; несовместимые окружения не объединяются.

## Что ещё предстоит измерить

Парная длительность включает работу движка, другие hooks, инструментирование, вытеснение и ожидания. Накладным расходам записи нужен отдельно объявленный сопоставимый контроль; аппаратной задержке — подходящее измерение поступления; FPS рендера — собственный поток; максимальной скорости нативных прогонов — эксперимент на пропускную способность. Архивная диагностика не устанавливает эти величины.

В [реестре стартовых попыток Windows](windows-input.ru.md) по-прежнему нет export схемы 7 и живой квалификации Windows. Проверки фокуса/перезапуска/прерывания, полный критерий M1, измеренные области допустимого ввода и откалиброванный на людях AR остаются открытыми.
