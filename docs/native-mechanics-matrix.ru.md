# Нативная матрица гравитации, размера, скорости и dual

[English version](native-mechanics-matrix.md) · [историческая матрица режимов](native-fixture-matrix.ru.md) · [контракт адаптера](native-adapter.ru.md)

Исследование расширяет выбранные нативные наблюдения полярностью гравитации, размером игрока, скоростью и активным dual. [Публичный каталог](../examples/native/mechanics-matrix.json) задаёт 11 коротких сгенерированных уровней с кубом, точные последовательности сырых значений и отклики на принадлежащие эксперименту планы ввода. Спецификация уровня сохраняет происхождение generated synthetic; выполненные записи и их проверки служат отдельными свидетельствами.

## Записываемые поля и точные значения

Схема нативной записи 3 добавляет три сырых поля каждого наблюдаемого PlayerObject и поле состояния игрового слоя. Схема каталога 2 задаёт требования к этим наблюдениям. Номера схем относятся к разным документам.

| Наблюдение | Сырое нативное поле | Смысл и граница |
|---|---|---|
| `gravity_inverted` | `PlayerObject.m_isUpsideDown`, boolean | Наблюдаемая полярность; величина гравитации и силы не калибруются. |
| `vehicle_size` | `PlayerObject.m_vehicleSize`, float | Сырое значение размера; форма коллизий не восстанавливается. |
| `player_speed` | `PlayerObject.m_playerSpeed`, float | Сырая настройка скорости; перевод в расстояние/время не измерен. |
| `dual_active` | `GJBaseGameLayer.m_gameState.m_isDualMode`, boolean | Наблюдаемая активность dual; отличается от начальной настройки уровня и существования указателя P2. |

Каталог сохраняет значения из проб, использованных при построении уровней. Ниже обозначения сокращают точные числа JSON; проверка не округляет их и не применяет допуск.

| Обозначение | Точное наблюдаемое значение |
|---|---|
| normal size | `1` |
| mini size | `0.6000000238418579` |
| S: slow | `0.699999988079071` |
| N: normal | `0.8999999761581421` |
| F: fast | `1.100000023841858` |
| FF: faster | `1.2999999523162842` |
| FFF: fastest | `1.600000023841858` |

Десятичные записи сохраняют наблюдения float32 после расширения. Это не измеренные множители скорости, физические единицы или оценки человеческой сложности. Числа не заменяют boolean: `true` не удовлетворяет числовому требованию `1`.

## Заданное построение

Во всех случаях P1 должен сохранять наблюдаемый режим cube до начала нативного завершения. Только dual задаёт покрытие активного P2 в режиме cube. Время ввода задано часами `processCommands_call_index`; `130/160` означает нажатие кнопки 1 на команде 130 и отпускание на 160. Обычные случаи сравнивают активный план с пустым принадлежащим эксперименту планом.

| Случай | Требуемая меняющаяся последовательность | План ввода | Механики, требуемые в обоих отсчётах отклика |
|---|---|---|---|
| `cube-reference` | Гравитация false, размер 1, скорость N, dual false | P1 `60/90` | Обычный куб, N, solo |
| `gravity-inverted` | Гравитация false → true | P1 `200/230` | Гравитация true, размер 1, N, solo |
| `gravity-cycle` | Гравитация false → true → false | P1 `200/230` | Гравитация true, размер 1, N, solo |
| `size-mini-cycle` | Размер 1 → mini → 1 | P1 `130/160` | Гравитация false, mini, N, solo |
| `speed-normal-cycle` | Скорость S → N → S | P1 `200/230` | Гравитация false, размер 1, N, solo |
| `size-mini-speed-fast` | Размер 1 → mini → 1; скорость N → F → N | P1 `190/220` | Гравитация false, mini, F, solo |
| `dual-independent` | Dual false → true → false; гравитация активного P2 true | P1 `130/160`; P2 `200/230` | Оба сравнения требуют dual true; гравитация P1 false, P2 true; размер 1 и N |
| `speed-slow-cycle` | Скорость N → S → N | P1 `130/160` | Гравитация false, размер 1, S, solo |
| `speed-fast-cycle` | Скорость N → F → N | P1 `130/160` | Гравитация false, размер 1, F, solo |
| `speed-faster-cycle` | Скорость N → FF → N | P1 `130/160` | Гравитация false, размер 1, FF, solo |
| `speed-fastest-cycle` | Скорость N → FFF → N | P1 `130/160` | Гравитация false, размер 1, FFF, solo |

Точные строки и требования к неизменным полям находятся в каталоге. Общий плоский уровень заканчивается обычным блоком в сырых координатах `(600, -15)`. Размер и скорость обычно меняются порталом в `(150, 15)` и восстанавливаются в `(450, 15)`. Случай normal начинается на slow через `kA4,1`, затем применяет порталы 201 и 200; портал normal при уже нормальном состоянии не дал бы свидетельства изменения. Комбинация mini/fast задаёт mini в `(150, 15)`, fast в `(220, 15)` и оба восстановления в `(450, 15)`.

Оба гравитационных уровня добавляют потолочные блоки на сырой Y 165, от X 120 до 540 с шагом 30, и портал перевёрнутой гравитации в `(150, 15)`. Цикл добавляет обычную гравитацию в `(450, 135)`. Геометрия даёт поверхность для позднего нажатия перевёрнутого куба; принятие случая всё равно зависит от сырых нативных наблюдений. Цикл требует восстановления до нативного завершения. Случай inverted не задаёт восстановления.

Dual устанавливает `kA10,1`, входит в dual объектом 286 в `(150, 15)` и возвращается в solo объектом 287 в `(450, 15)`. Контроль `drop-p1` сохраняет полный план P2, а `drop-p2` — полный план P1. Каждое сравнение исключает только исследуемый канал. Требования P2 используют только отсчёты активного dual и ничего не утверждают о неактивном P2 до входа или после возврата.

При построении использованы две отдельные серии проб на 33 и 10 записей, сохранённые в игнорируемых каталогах `reports/native/mechanics-probe-4aff4018d4bd4f038b778cee7c3bf85c/` и `reports/native/mechanics-followup-90005ba4f3b248249ce9e7d5049a61f1/`. Первые гравитационные пробы завершались и записывали нативные callbacks нажатия/отпускания, однако не установили отклик `y`/`y_velocity` для тех планов. Сохранённые записи послужили основанием для добавления потолка и более позднего ввода. По пробам выбраны конечные требования; это не независимые подтверждающие повторы, и они не объединяются с подтверждающей матрицей.

Три ранние попытки harness также сохранены отдельно. Запуск остановился до экспортированной записи в `reports/native/mechanics-final-0b11bbd-67b9b205788e4a4d82fd70479600fffd/` и `reports/native/mechanics-final-confirmed-37298b4dc2284ef7bb79848beb99506b/`. Подготовка остановилась до запуска в `reports/native/mechanics-final-confirmed-137132586f5144e7ac2098e1987ed5b1/`, поскольку существующий executable sandbox оставался заблокированным. Ни одна попытка не дала вердикта матрицы; все три аудита восстановления четырёх файлов прошли. Теперь подготовка пропускает копирование только при совпадении SHA-256 источника и назначения; изменённое содержимое по-прежнему требует копирования и может вызвать ошибку блокировки. Более поздняя одиночная проба в `reports/native/startup-probe-3141448277aa4aa79cfd911d530a2681/` завершилась при временном запросе состояния выполнения системы/дисплея. Это не устанавливает причину ранних ошибок запуска и не объединяется с подтверждающей матрицей.

## Контракт принятия

`fixture-check` требует точный SHA-256 уровня, полный `level_start`, заявленный режим ввода и полный план, успешные соответствующие нативные push/release callbacks к терминальному событию, явный ожидаемый исход и точные последовательности режимов/механик. Наблюдательная базовая попытка не имеет запланированного принадлежащего эксперименту ввода и записывает `input_source: unknown`; наблюдаемые нативные callbacks, включая отпускания при очистке, сохраняются. Их присутствие не устанавливает человеческое авторство.

Покрытие режимов и механик использует строки, в которых **оба** нативных флага false: `level_end_animation_started` и `has_completed_level`. Отсчёты анимации завершения и терминального события не могут удовлетворить покрытие. Последовательность каждого поля отдельно сжимается по повторяющимся значениям, сохраняя точный порядок без соседних дублей. Отдельные последовательности сами по себе не доказывают совместное присутствие значений. Null означает отсутствие требования, а не измеренное отсутствие механики. Нативные записи схем 1/2 не удовлетворяют требованиям механик схемы 3. Покрытие активного P2 дополнительно требует фактический `dual_active: true` и доступные отсчёты P2.

Три активных воспроизведения должны совпасть по **всей записанной трассе до терминального события включительно**. Фильтр покрытия до завершения на это сравнение не распространяется. Схема 3 сравнивает все выбранные поля игроков, включая сохранённые значения неактивного P2, и сохраняет наблюдения схемы 2. Её 14 точных компонентов:

```text
planned_inputs_equal                  recorded_inputs_equal
recorded_call_arguments_equal         recorded_player_fields_equal
terminal_callback_and_placement_equal terminal_player_fields_equal
recorded_native_phase_equal           recorded_update_context_equal
delivered_update_records_equal        delivered_scheduler_records_equal
native_phase_events_equal             terminal_phase_and_context_equal
recorded_dual_active_equal             terminal_dual_active_equal
```

Сравнение полей игроков включает положение, скорость Y, вращение, смерть, режим, гравитацию, размер и скорость. Dual слоя сравнивается в каждой строке и терминальном событии. Переданные аргументы update/Scheduler, группировка вызовов и нативные фазы остаются точными. Исходные входящие аргументы времени, настенная частота и заблокированные запросы неизвестного происхождения остаются диагностикой вне этого вердикта; см. [исследование часов](clock-investigation.ru.md).

`fixture-response` сравнивает два принадлежащих эксперименту плана. Обе записи должны удовлетворять своим требованиям и иметь одинаковые идентичности окружения/коллектора и начальное выбранное состояние. Префикс состояния исследуемого игрока и сырое значение dual должны совпадать до первого отличающегося запланированного события. Отклик требует различия заявленных `y` или `y_velocity` на общем индексе команды не раньше этого события, при нужном режиме, **выполнении всех ненулевых предикатов механик в обоих отсчётах** и до нативного завершения в обеих записях. Для P2 в обоих отсчётах всегда требуется активный dual. Различие только после завершения, при другой механике или до изменения ввода не проходит. Поля измеряются после `processCommands`; значения непосредственно в callback ввода не установлены.

Случай runner проходит только при совпадении всех проверок записей, статусе каждого отклика `selected_response_observed`, повторном сравнении `recorded_subset_consistent` и явных ожидаемых исходах. Исследовательский `any_terminal` не закрывает проверку. Структурно корректное несоответствие может завершить CLI с кодом ноль, поэтому runner читает вердикты JSON, а не подменяет измеренное согласие успехом команды.

## Воспроизведение и сохранённые артефакты

Запускать из корня репозитория после [закреплённой настройки адаптера](native-adapter.ru.md). Одна сборка не доказывает выполнение. Каталог по умолчанию остаётся исторической матрицей, поэтому новый каталог нужно указать явно:

```powershell
uv sync --locked --extra dev
.\.venv\Scripts\python.exe -m axiom fixtures .\examples\native\mechanics-matrix.json
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-native.ps1 -Jobs 4
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-native-matrix.ps1 -GameDirectory 'C:\path\to\Geometry Dash' -MatrixPath .\examples\native\mechanics-matrix.json -Repetitions 3 -ClockPolicy fixed-scheduler-240
```

`fixed-scheduler-240` передаёт float32 `1/240` фактическим callbacks Scheduler на протяжении защищённого изолированного процесса. Это явное вмешательство в часы; оно не доказывает 240 настенных Гц или эквивалентность обычному вводу. Эксперименты `native` и `fixed-base-60` принадлежат отдельным часовым областям. `-CaseId dual-independent` выбирает подмножество, а `-OutputDirectory` — новый каталог свидетельств. Существующий каталог сохраняется и отклоняется; число повторов ограничено 2–16, уже работающий sandbox предотвращает параллельный эксперимент.

Runner записывает хеши исходного/валидированного каталога, коммит оценщика и хеши четырёх файлов анализа, фактические идентичности коллектора/окружения, хеши записей и сравнений, доступность/последовательности механик, вердикты и предикаты/первые различия откликов. Он сохраняет и восстанавливает байты и существование изолированных fixture, replay, настроек AXIOM и loader, запускает процесс скрыто и завершает только собственный процесс. Это сохранность четырёх файлов эксперимента, а не полная ведомость личных сохранений. Сырые записи, бинарники/ресурсы игры и сохранения остаются вне Git. Аудит на том же компьютере проверяет сохранённые артефакты и не устанавливает независимое внешнее воспроизведение.

На время матрицы harness запрашивает у Windows состояние выполнения системы/дисплея, записывает `startup_execution_state: system_and_display_required_during_matrix` и восстанавливает предыдущий запрос потока в `finally`. План электропитания пользователя и игровой ввод не меняются. Это заявленный контекст harness; он не делает неполное окружение записи исчерпывающим.

Существующие свидетельства можно проверить офлайн:

```powershell
.\.venv\Scripts\python.exe -m axiom fixture-check .\examples\native\mechanics-matrix.json .\reports\native\mechanics-<id>\gravity-cycle\replay-1.json --case gravity-cycle --run replay
.\.venv\Scripts\python.exe -m axiom fixture-response .\examples\native\mechanics-matrix.json .\reports\native\mechanics-<id>\dual-independent\drop-p2-1.json .\reports\native\mechanics-<id>\dual-independent\replay-1.json --case dual-independent --check p2-response
```

## Первичные источники и оставшиеся ограничения

Типы полей взяты из [закреплённых bindings Geode для 2.2081](https://github.com/geode-sdk/bindings/blob/2a8b5c489ce8b49e7061b0543aa2bc5b22570063/bindings/2.2081/GeometryDash.bro#L14799-L14820), включая [dual в GJGameState](https://github.com/geode-sdk/bindings/blob/2a8b5c489ce8b49e7061b0543aa2bc5b22570063/bindings/2.2081/GeometryDash.bro#L8958-L8965) и [свойства заголовка уровня](https://github.com/geode-sdk/bindings/blob/2a8b5c489ce8b49e7061b0543aa2bc5b22570063/bindings/2.2081/GeometryDash.bro#L12637-L12650). `m_playerSpeed` участвует в [нативной скорости X вместе с другим множителем](https://github.com/geode-sdk/bindings/blob/2a8b5c489ce8b49e7061b0543aa2bc5b22570063/bindings/2.2081/inline/PlayerObject.cpp#L338-L340), поэтому не является полной скоростью.

[Закреплённый генератор](https://github.com/gdsolver/gdsolver/blob/8e8d69ada86a315c71d05cc8b8fe4d369d883aa2/py/mklevel.py#L63-L69) solver для GD 2.2081 указывает гравитацию 10/11 и обычный/mini размер 99/101; его [наблюдения координат](https://github.com/gdsolver/gdsolver/blob/8e8d69ada86a315c71d05cc8b8fe4d369d883aa2/py/mklevel.py#L77-L84) описывают сырую Y плюс 90 как мировую Y. [Архивные определения gd.py](https://github.com/nekitdev/gd.py/blob/f2c1c74bdeb55bbe8e1233ec2f04098ef043f5c8/gd/enums.py#L1185-L1219) дают dual/solo 286/287 и скорости 200/201/202/203/1334. Старая библиотека помогает построить пробу, но не удостоверяет поведение текущего движка. Фактические сырые наблюдения AXIOM определяют, произошли ли заявленные переходы и отклики.

Исследование охватывает один выбранный режим, пять сырых состояний скорости, две полярности гравитации, два размера, одну комбинацию mini/fast и один dual-уровень с независимым вводом кубов. Все сочетания и механики этих режимов не охвачены. Окружение/настройки и выбранное состояние движка остаются неполными; поступление аппаратного ввода, эквивалентность обычному вводу, накладные расходы, прерывания/reset/focus, триггеры/RNG, восстановление checkpoints и более сложные коллизии остаются открытыми. M1 не закрыт. Конечная матрица принадлежащих эксперименту воспроизведений не доказывает непрерывный интервал тайминга, невозможность, человеческий предел или откалиброванный Axiom Rating реального уровня.
