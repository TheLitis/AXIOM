# Наблюдения ввода Windows → игра

[English version](windows-input.md) · [Нативный адаптер](native-adapter.ru.md) · [Наблюдения UILayer](input-observation.ru.md) · [Записанный replay](recorded-replay.ru.md) · [Roadmap](roadmap.md)

**Реализация, программные проверки и нативная сборка готовы; живая квалификация Windows не установлена.** Наблюдатель схемы 7 по явному включению добавляет вход Windows и публичные события Geode к прежним квитанциям UILayer, нативной очереди и игрока. Две стартовые попытки с новым пакетом и отдельный стартовый контроль со старым пакетом не дали exports. Завершённого наблюдения схемы 7, аутентификации устройства или эквивалентности обычного ввода нет. Исторические наблюдения схемы 5 и записанные replay схемы 6 сохраняют исходные данные и область проверки.

Этот путь использует `windows-input: raw-dispatch-v1`, нативные часы и driver `none`, без плана replay или вмешательства в часы. Он наблюдает существующий процесс игры; не генерирует ввод, не регистрирует другой Raw Input receiver, не меняет payload событий и не потребляет приватную очередь Geode.

## Отдельные ступени наблюдения

| Ступень | Записываемая область | Ограничение |
|---|---|---|
| Вход сообщений Windows | Выбранные сообщения основного HWND игры и скрытого HWND `GD_RawInput`; сырые payload клавиатуры и кнопок мыши | Квитанция сообщения/чтения не аутентифицирует оборудование и не доказывает доставку в gameplay |
| Публичные события Geode | Typed snapshots клавиатурных code/action/native-code/timestamp/modifier и мышиных button/action/timestamp/modifier | Другие listeners могут изменить или остановить mutable event; snapshot не доказывает конечную маршрутизацию |
| Вход UILayer | Прежние наблюдения клавиш и touch begin/end/cancel активного игрового слоя | Правая/средняя кнопка мыши не обязана стать touch или игровым действием |
| Нативная обработка / игрок | Прежние снимки очереди, канал requested и фактический push/release actor/native return | Запрос с меткой P2 может дойти до P1; сохраняются оба наблюдения без переписывания меток |

Запись сырых клавиш и кнопок ограничена активной попыткой, когда основное HWND игры находится в foreground. Фоновые события и трафик только движения дают skip counts, а не доказательство gameplay. Сообщения фокуса основного окна остаются отдельными наблюдениями. Сырой device handle (`hDevice`) не сохраняется; нет глобального журнала клавиатуры, сбора текста/буфера обмена или заявления об идентичности физического устройства.

## Запись схемы 7

Только явно выбранный наблюдатель Windows использует схему 7, сохраняя `attempt.windows_input` вместе с прежними игровыми потоками. Исторические схемы 1–6 неизменны.

| Поле | Контракт |
|---|---|
| `enabled`, `scope`, `main_thread_id`, `windows` | `active-guarded-sandbox-attempt-foreground-raw-only`; main/raw roles с process/thread/HWND и installed status |
| `messages` | До 2048 упорядоченных парных WNDPROC receipts, вложенность внутри потока, foreground до/после, wall/input timestamps, сырые параметры сообщения и точный нативный LRESULT |
| `raw_input` внутри сообщения | Клавиатура: kind/vkey/scan_code/flags/keyboard_message; мышь: kind/button_flags; без device handle или payload движения |
| `sdk_events` | До 2048 публичных typed snapshots событий, phase/context и один `queue_snapshot` на входе; без перехвата приватной очереди |
| `integrity` | `overflow_count`, `read_error_count`, `pending_callbacks_at_snapshot`, `errors`; неполные наблюдения не устанавливают результаты ведомости |
| `skipped` | `background_raw_count`, `mouse_motion_count`, `unsupported_raw_count` |
| Timestamp/listener metadata | `Geode-getInputTimestamp-QPC-seconds`, `public-global-listener-receipt`, priority `INT_MIN` |

Inspector выдаёт `windows_input_observations`. Публичный глобальный listener передаёт события без изменения данных, но может не увидеть событие, остановленное в более раннем key-specific port. Парный выход сообщения может последовать за нативным terminal при завершении уже начатого callback; такой выход не становится вновь выведенным игровым действием после финиша.

## Жизненный цикл и время

Закреплённый [маршрут Windows в Geode](https://github.com/geode-sdk/geode/blob/2a5fd87433da47d6bf07221774f0cbb25535ae08/loader/src/platform/windows/input.cpp#L660-L715) асинхронно находит `GD_RawInput` в другом потоке. Windows subclass helpers [нельзя использовать между потоками](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/nf-commctrl-removewindowsubclass). Цепочка WNDPROC в одном процессе через [`SetWindowLongPtrW`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowlongptrw) — отдельный механизм: сохраняется предыдущая procedure, каждое сообщение передаётся один раз, ошибки attach/detach или замена цепочки записываются. Одного обнаруженного HWND недостаточно для вывода о безопасном жизненном цикле.

[`GetRawInputData`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getrawinputdata) читает пакет по ссылке `WM_INPUT`; статус чтения и сырые flags сохраняются до передачи сообщения. AXIOM не должен заменять существующую [регистрацию Raw Input](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerrawinputdevices): внутри процесса выбирается одно окно-получатель на класс устройств. Поля пакета Windows и коды Cocos остаются разными namespaces. Keyboard break/extended flags, повторные down и комбинированные flags кнопок мыши сохраняются как наблюдения; они не сворачиваются в предполагаемые физические действия.

[`GetMessageTime`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmessagetime) описывает время создания последнего полученного сообщения очереди в миллисекундах с переполнением; этот контракт не записывает такое значение. Закреплённый [`getInputTimestamp`](https://github.com/geode-sdk/geode/blob/2a5fd87433da47d6bf07221774f0cbb25535ae08/loader/src/platform/windows/util.cpp#L445-L455) Geode читает QPC/frequency при упаковке ввода. Записанные wall timing наблюдателя, timestamp Geode, сырой touch timestamp и command/update/Scheduler membership остаются отдельно обозначенными. Ни одно не становится измеренным временем аппаратного поступления, непрерывным окном ввода или аутентифицированной задержкой.

Geode передаёт сырые события через приватную mutex queue и обрабатывает их позднее; вне foreground основного окна очередь может очищаться. Callback фокуса может внутренне создать key-up события. Поэтому отпускание в dispatcher не требует соответствующего записанного Windows break, а близость времени не устанавливает вложенность между потоками.

## Контракт сопоставления

Протокол `windows-raw-sdk-ui-compatible-candidates-v1` сохраняет **кандидаты**. Совместимость raw Windows → Geode требует совпадения native key/scan/направления или flags кнопок мыши и timestamp Geode внутри точного записанного интервала `input_timestamp_enter`/`input_timestamp_exit` сообщения, без допуска по близости wall time. Повторный down остаётся отдельным в SDK snapshot, но соответствует сырому down. Совместимость Geode → UILayer требует одинакового потока, наблюдаемого порядка и точного key/направления/timestamp; кандидаты мыши требуют left press/release, соответствующего touch begin/end.

Отчёт сохраняет `no_compatible_candidate`, `one_compatible_candidate` и `ambiguous_compatible_candidates`, все сырые записи и несопоставленные sequences. Несопоставленное lifecycle message не объявляется потерянной клавишей. Единственный кандидат остаётся наблюдаемой связью по этому правилу, без аутентификации оборудования или доказательства записи каждой промежуточной ступени очереди.

Typed события правой/средней кнопки наблюдаются отдельно; их отсутствие в UILayer или gameplay не исправляется выдуманными touch/player квитанциями. Cancellation сохраняется как cancellation, а не выдуманное отпускание. Потеря фокуса, пауза, reset и ранний выход остаются разными исходами; одно наблюдение смены фокуса не квалифицирует завершённое восстановление после него. Пауза закрывает активное наблюдение на записанной границе abort, поэтому последующие отпускания, созданные при смене фокуса, могут остаться вне capture. Связи отпусканий сообщаются только для фактически сохранённых callbacks.

## Ручной сценарий

Используйте локально установленную закреплённую игру и новые изолированные каталоги runtime/данных:

```powershell
uv sync --locked --extra dev
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-native.ps1 -Jobs 4
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-native-windows-input.ps1 -GameDirectory 'C:\path\to\Geometry Dash' -TimeoutSeconds 600
```

Runner явно включает capture через `--geode:axiom.native-capture.capture`, выбирает изолированный sandbox и `windows-input=raw-dispatch-v1`; по умолчанию также выбирается `sandbox-manual`. Необязательный `-NativePackage` выбирает явный пакет; `-AutomaticStart` пропускает ожидание меню и запускает fixture без генерации человеческого ввода. Необязательный runtime должен быть новым каталогом под `.tools` workspace, а выходные данные — новым каталогом внутри workspace. Эти параметры не превращают последующие наблюдения в аутентифицированные действия оператора. Ручной сценарий — будущий критерий при наличии оператора; завершённое ручное наблюдение Windows в этой точке не записано.

1. Дождитесь готовности и используйте **Start AXIOM Test**, если автоматический старт не выбран явно.
2. В gameplay отдельно нажмите/отпустите Space, W, Up, A, D, Left и Right; используйте S как дополнительный наблюдаемый код.
3. Подержите одну клавишу достаточно долго для появления повторов, затем отпустите. Сохраняются все повторы/отпускания, а не ожидаемая одна пара down/up.
4. Внутри gameplay отдельно нажмите/отпустите левую, правую и среднюю кнопки мыши. Дополнительные кнопки необязательны и считаются проверенными только при наблюдении.
5. Дайте fixture завершиться. Сообщение оператора сохраняется отдельно от нативных данных и не меняет записанное provenance.

Опыты фокуса/паузы/reset выполняются отдельными объявленными попытками с сохранением прерывания, без объединения с успешным финишем. Timeout включает ожидание меню. Runner сохраняет неудачные старты и inspections, фиксирует идентичности исходников/пакета/уровня/анализа и восстанавливает исходное существование и байты четырёх файлов эксперимента. Captures остаются в игнорируемых локальных данных; файлы игры и приватная телеметрия не публикуются в Git.
