# Автоматический нативный исполнитель проб

[English version](native-probe-executor.md) · [Конвейер проб](probe-engineering.ru.md) · [Нативный адаптер](native-adapter.ru.md)

`axiom probe-run` получает зафиксированный пакет `probe-export` и последовательно исполняет задания через Windows sandbox. Для каждой попытки создаются новый runtime, явный replay, сохранённая запись либо ошибка исполнения и файлы промежуточных результатов. Python проверяет нативный terminal и идентичность условий перед включением результата в дискретную карту.

Это реализованный путь исполнения; при разработке и проверке данного изменения Geometry Dash не запускалась. Синтетические записи проверяют программное ядро, настоящие консольные процессы — примитивы Windows. Подтверждённая нативная измерительная кампания, полные критерии M1/M2, соответствие обычному вводу и человеческая калибровка остаются открытыми.

## Входные данные и запуск

Для live backend нужны:

- Настоящая завершённая запись схемы 4/5 с настоящего начала, заявленным происхождением `native-engine-capture`, вводом `owned-pre-command` и часами `fixed-scheduler-240`. Весь объявленный план ввода должен быть исполнен. Заявленное происхождение не является независимой аутентификацией.
- Точные байты plain level, игрового executable и DLL адаптера внутри пакета, указанные в источнике. Несовпадающие хеши отклоняются. Подготовка sandbox сейчас поддерживает закреплённую установку Windows x64 / GD 2.2081 / Geode 5.8.2.
- Checkout AXIOM со скриптами PowerShell и обычным каталогом `.tools`. Указывай `--workspace` явно, в том числе при установке Python-пакета из wheel.
- Новый выходной каталог внутри checkout, вне исходного exchange. Его обычный родительский каталог должен существовать. Прежние данные сохраняются; неявного продолжения и замены нет.

Пути ниже обозначают существующие локальные нативные артефакты; они не поставляются как примеры. Замени пути игры/пакета на установленную закреплённую игру и пакет с DLL, совпадающей с хешем источника. Публичный синтетический источник из `examples/probes` этот live backend намеренно отклоняет.

Небольшой `reports/native/full-start-reference/probe-spec.json` может проверять первое запланированное событие:

```json
{
  "schema_version": 1,
  "kind": "native_probe_spec",
  "id": "native-first-event-grid",
  "axes": [{"event_index": 0, "offsets_commands": [-1, 0, 1]}],
  "repetitions": 3,
  "run_budget": 9
}
```

Из настоящего checkout AXIOM, с новыми путями study/exchange/выхода:

```powershell
uv sync --locked --extra dev
$workspaceRoot = (Get-Location).Path
uv run --locked axiom probe-plan `
  reports/native/full-start-reference/capture.json `
  reports/native/full-start-reference/probe-spec.json `
  --json reports/native-probe-study.json
uv run --locked axiom probe-export reports/native-probe-study.json `
  --output reports/native-probe-exchange
uv run --locked axiom probe-run reports/native-probe-exchange `
  --workspace $workspaceRoot `
  --game-directory "C:\Games\Geometry Dash" `
  --native-package "C:\local-artifacts\reference-adapter\axiom.native-capture.geode" `
  --level reports/native/full-start-reference/level.txt `
  --output reports/native-probe-run-01 `
  --timeout-seconds 90 --max-jobs 3
```

Первые три запланированных задания здесь — повторы baseline. `--max-jobs 3` намеренно оставляет последующие задания сетки невыполненными и не устанавливает полноту сетки. Недопустимые сдвинутые расписания не имеют задания и не становятся нативными смертями. Смещения остаются целыми индексами вызовов `processCommands`, а не физическими миллисекундами.

| Параметр | Поведение |
|---|---|
| `--timeout-seconds` | Целое 30–600; по умолчанию 90. Срок игры/export контролирует worker. Подготовка и очистка могут добавить время. |
| `--max-jobs` | Целое 1–4096, ограниченное числом запланированных заданий. По умолчанию — все задания. Явный неполный бюджет сохраняет пропущенные повторы. |
| `--keep-going` | Продолжать после ошибок исполнения/записи. Неудачное задание не повторяется. Отмена и проверки неизменности ввода сохраняются. |

Live worker копирует не более 1 MiB plain level и 16 MiB на replay/запись. Нужны пути локального диска, обычные файлы и предки; traversal, alternate streams и перенаправленные входные пути отклоняются. Это текущие ограничения реализации.

## Исполнение и владение

`axiom.probejobs.load_probe_exchange` восстанавливает всё исследование и каждое сгенерированное задание в точном порядке. Exchange содержит только `jobs.json`, `study.json` и уникальные запланированные `plans/pNNNN.json`. Канонические байты replay — компактный UTF-8 JSON с сортированными ключами и одним LF в конце. Хеш исходного файла study, канонический хеш study и хеши файлов replay различаются.

Исполнитель копирует точные байты exchange в новый выходной каталог и проверяет снимок. Исходный и сохранённый инвентари проверяются перед каждой попыткой и после завершения планирования. Для игры/пакета/уровня/worker создаётся отдельный инвентарь хешей; точный уровень сохраняется локально. Проверки обнаруживают изменения на указанных границах и не блокируют все входные файлы на всю кампанию.

Для каждого задания backend пишет `request.json` и запускает отдельный worker PowerShell. Worker:

1. Получает исключительную lease общего изолированного профиля `%LOCALAPPDATA%\AXIOMSandbox`. Уже работающий sandbox или другой владелец lease приводит к отказу.
2. До подготовки снимает четыре экспериментальных файла и создаёт новый runtime внутри `.tools` checkout. Между заданиями профиль общий и защищён lease; заново на каждый job он не создаётся.
3. Копирует точные уровень и replay, проверяет подготовленные хеши и запускает `AXIOMSandbox.exe` с явными флагами полного replay, owned-input и фиксированного Scheduler.
4. Создаёт игру приостановленной, присоединяет к принадлежащему worker Windows Job Object и только затем продолжает исполнение; сохраняет handle процесса. Worker не завершает процессы, выбранные по имени либо переиспользованному PID.
5. Ожидает одну новую стабильную запись до игрового deadline, копирует байты и закрывает интервал export очисткой принадлежащих процессов. Второй export, изменившийся источник записи либо изменение прежней записи отклоняет результат.
6. Отдельно фиксирует состояние выхода до очистки и запрос завершения; завершает свою игру и Job, до 30 секунд ожидает нулевого числа активных процессов Job, включая потомков, затем закрывает Job. Независимо восстанавливает/проверяет каждый экспериментальный файл перед освобождением lease. Неудача ожидания остаётся явной ошибкой очистки.

Эти четыре файла — runtime `fixture-level.txt`, профильные `axiom.native-capture/replay.json`, `axiom.native-capture/settings.json` и `geode.loader/settings.json`. Восстановление сохраняет байты и прежнее отсутствие. Ошибка одного файла не отменяет попытки восстановить остальные. Любой сбой очистки/сохранности становится ошибкой исполнения. Эта область охватывает четыре экспериментальных файла, а не резервную копию всех сохранений или настроек ПК.

Worker передаёт запланированный внутриигровой ввод без инъекции ввода Windows/устройства. Нативная смерть — допустимое terminal-наблюдение; выход процесса, timeout, отмена, отсутствие записи и ошибка очистки не становятся смертью или финишем.

## Отмена и сохранённые результаты

Ctrl+C во время ожидания native worker запрашивает согласованную отмену через `cancel.request.json` внутри попытки. Python продолжает ожидать, пока worker выполняет очистку и восстановление. Он не принудительно завершает PowerShell до `finally`. Если передать запрос не удалось, остаётся игровой deadline worker. Ctrl+C между заданиями может прервать публикацию файла: гарантируются только уже опубликованные checkpoints, а не новый итоговый отчёт. Общий синхронный интерфейс Python `CaptureBackend.run` либо синтетического callback не имеет автоматического срока для произвольного кода callback.

Выходной каталог содержит:

| Путь | Назначение |
|---|---|
| `exchange/` | Точные исходные байты exchange и их файловый инвентарь |
| `backend-inputs.json`, `level.txt` | Хеши live backend и точный уровень, если подготовка дошла до публикации |
| `attempts/<trial_id>/request.json` | Запрос worker, связанный хешем |
| `attempts/<trial_id>/attempt.json` | Дескриптор записи/ошибка worker, timeout, выход до очистки и четыре записи сохранности |
| `attempts/<trial_id>/capture.json` | Неизменённая запись, если скопирована; сохранение файла само по себе не означает принятие |
| `attempts/<trial_id>/executor-observation.json` | Проверка записи либо явная ошибка исполнения |
| `attempts/<trial_id>/*.stdout.txt`, `*.stderr.txt` | Раздельные консольные данные worker/игры |
| `check-NNNN.json` | Manifest импорта отдельной записи |
| `results-NNNN.json` | Новый накопительный checkpoint после каждой предпринятой попытки |
| `results.json` | Итоговый `native_probe_results`, включая неполную серию |
| `map.json` | Дискретная карта повторённых проб, когда построение успешно |
| `executor.json` | Планирование, ошибки, счётчики, хеши артефактов и область исполнения |

Python публикует checkpoints атомарно без замены прежних файлов. Исключения, некорректные записи, повторные хеши/attempt IDs и несовпадающие условия источника остаются ошибками или отклонениями. Невыполненные задания остаются пропусками. Ошибка подготовки backend после снимка exchange сохраняет `preflight_error`, results/map со всеми пропусками и отчёт исполнения, без вызова заданий. Сбой итогового построения карты сохраняет `executor.json` с `map_path=null`, `map_sha256=null` и явным `map_error`.

Счётчики учитывают полноту свидетельств: `native_launch_attempts` — подтверждённая нижняя граница; `native_launch_uncertain_attempts` считает вызовы worker без валидных итоговых сведений о запуске. `new_native_execution` равен `true` при любом подтверждённом запуске, `null` при отсутствии подтверждённых запусков и наличии неразрешённого вызова, иначе `false`. Потерянный результат worker не доказывает, что игра не запускалась.

CLI возвращает `0` после серии без ошибок либо явного неполного бюджета, `2` при ошибках исполнения/записи/preflight/целостности/карты и `130`, когда итоговый `stop_reason` равен `cancelled`. `--keep-going` не превращает серию с ошибками в код `0`. Прежние checkpoints остаются доступными при сбое последующей публикации.

## Программные проверки и оставшаяся квалификация

```powershell
uv run --locked pytest tests/test_probejobs.py tests/test_nativeprobe.py tests/test_probeadapter.py tests/test_probes.py -q
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-native-probe-process.ps1
uv run --locked ruff check .
uv run --locked ruff format --check .
```

Проверки процессов Windows запускают настоящие консольные процессы и файловые сценарии восстановления. Тесты backend, создающего записи, используют явно синтетические fixtures. Это инженерное изменение не включает живой прогон GD или измерение физических окон. Нативной кампании ещё нужно подтвердить повторяемость полных стартов, контроли, отложенные отказы и поддерживаемые конфигурации. Дискретные пробы не закрывают M1/M2 и не устанавливают человеческие вероятности, невозможность или реальные AR.
